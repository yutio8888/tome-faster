# 0.2.5：快捷栏、地图遮罩与保存分配优化

2026-09-13；ToME 1.7.6，固定引擎 `624a67329fe2ad440c5b344785a9c73fcf22ae63`。
本轮在 0.2.4 基础上增加三项生产优化。移动场景的快捷栏绘制 CPU 减少约 24%；地图遮罩减少逐格绘制调用；保存回调减少临时 Lua 分配。**未据此宣称整体战斗或保存长帧已经解决。**

所有真实游戏测试使用用户原始 ZIP 的独立副本，Linux / Xvfb 1280×800、约 30 FPS、Mesa llvmpipe 软件渲染、游戏内嵌 LuaJIT 2.0.2。没有硬件 GPU 或 Windows/macOS 数据。
正式分项 A/B 各三组，顺序后/前、前/后、后/前，`detail=false`；同一分项仅切换对应配置。结果见 [渲染数据](render-save-results.json) 和 [保存数据](save-followup-results.json)。

## 快捷栏文字缓存

[FasterHotkeys.lua](../overload/engine/FasterHotkeys.lua) 识别原 `HotkeysIconsDisplay.display`，仅替换三次 `font:draw` 表达式。
技能可用性、冷却、数量、物品查找、页码、选中、拖拽、字体样式切换和原 `toScreen` 合成仍按原顺序执行。
缓存键包括字体身份、实时样式、文本、宽度和颜色；普通中文/UTF-8 可缓存，格式控制文本和特殊 UID 绘制回退。

全局最多 512 项 / 4 MiB 纹理像素预算，FIFO 淘汰。字体、界面 surface、尺寸、缩放、分辨率、语言、字体渲染设置变化会失效。
缓存弱持有 UI owner；不把缓存写进游戏快照。每次返回新的行元数据，避免调用者修改影响后续帧。
命中时先绑定专用 1×1 纹理，再绑定缓存文字，处理引擎跨纹理单元共享绑定缓存的情况；额外 4 bytes 计入预算。
预算不等于进程 RSS，未包括驱动和分配器额外开销。

三次各 60 次移动，均 61 次完整快捷栏 `display`：

| 每进程均值的中位数 | 关闭 | 开启 |
| --- | ---: | ---: |
| 每次快捷栏绘制 CPU | 1.156 ms | 0.883 ms |
| 快捷栏绘制总 CPU | 70.496 ms | 53.846 ms |
| 移动阶段缓存命中 | 0 | 1260 |

每次绘制 CPU 少 **23.62%**。另一次 LD_PRELOAD 归因运行确认移动的原生 TTF 光栅化从 1260 次变为 0 次；缓存后只首次创建 1×1 绑定纹理。
归因运行包含原生计时扰动，不混入正式 A/B。战斗敌人、随机轨迹、动作数和帧数不同，不将战斗总耗时比值解释为确定加速。

## 地图特效遮罩批处理

[FasterEffectMask.lua](../overload/engine/FasterEffectMask.lua) 缓存有序格子对应的原生顶点，使用内置 `newVO/addPoint/toScreen` 将每个特效的 N 个四边形合为一次调用。
每帧仍清空并重建公开 `Map.fbo`，随后执行原 shader、动画帧推进、FOV 和最终合成。
**本版没有缓存最终遮罩像素，也没有省略 FBO 清屏或光栅化。** 这样保留其他显示调用对公共 FBO 的观察和原合成时序。

缓存最多 32 项 / 4 MiB 保守估算的原生顶点内存，每个特效最多 4096 格，不新增 FBO。
身份、实际有序格集合、位置、缩放、viewport、材质或遮罩参数变化时重建；负数及小数坐标按原 C 绑定逐项截断。
map、effect、FBO、材质库弱持有；自定义元方法、未知原生绑定和不支持的格集合回退。
标准 MapEffect 实例允许已识别类的纯表继承链，包括本体类模块的空终端元表。
顶点准备和 Lua 分配在原生遮罩 FBO 绑定前完成；绑定内只作原生绘制与数值计数。新增真实 FBO 析构反例验证该顺序，未知自定义 FBO 仍在原时点执行原循环。

三次真实战斗中，优化侧分别完成 34 / 40 / 20 次遮罩批量绘制，省去 729 / 722 / 380 次逐格调用，缓存命中 30 / 38 / 19 次；均无回退。
各次战斗长度不同，因此这些是工作量减少的证据，不是整体战斗速度的可比百分比。
最初的 `stutter-map-v1-*` 及 guard probe 暴露了标准实例/空终端元表兼容遗漏，已修复并补测试；正式记录使用 `stutter-map-v3-*`。

另以原 target_fbo shader、真实可见性入口和三个合成特效比较 48 个连续帧：完整输出、公共遮罩、GL 状态、FOV 查询及动画均一致。
受控的三组各 120 帧计时中，原版/批处理 CPU 中位数 29.555 / 29.769 ms，提交 wall 2664.132 / 2679.826 ms；每组省去 6600 次调用，但未测得稳定时间收益。
计时内两侧均暂停 GC，pair 边界回收不计时；无 readback 或显式 GL 同步，该实验不是常规游戏或 GPU 完成时长测量。

## 保存与剩余候选

[FasterSaveFollowup.lua](../overload/engine/FasterSaveFollowup.lua) 在同一 Savefile 内共享两个原生序列化回调。
完整保存实测 2854 次对象调用全部命中，仅创建两组回调；原三个完整 GC、对象序列化次序、yield、错误和 worker 协议保留。
2,853 对象微基准少分配约 397.5 KiB / 13.77%；完整保存没有稳定 CPU 或最长帧改善。
详见 [保存实现、实测与候选裁决](save-followup.md)。

剩余项逐项处理结果：

| 原候选 | 本轮结果 |
| --- | --- |
| 快捷栏稳定文字缓存 | 已实现并分项测量 |
| 地图静态遮罩缓存 | 交付有界顶点批处理；最终像素缓存未实现，公共 FBO 和动态合成保留 |
| 相邻完整 GC 合并 | 真实 finalizer/weak 反例不等价，未采用 |
| 增量 GC 到首个完成信号 | 旧周期完成不等于新完整屏障，未采用 |
| 持久化白名单直接裁 Game 根 | exporter 实际依赖 uiset/calendar 等，未采用；已完成真实根图计数和消费者审计 |
| 冻结快照切片、允许继续游戏的导出 | 完整事务/写屏障尚未实现，仍保留同步快照 |
| 每对象提前唤醒原 worker | 固定 C worker 实验会重复 CREATE/关闭同名归档，未采用 |
| Fearscape captive / 旧背包引用规范化 | 未迁移旧引用；需要对跨层引用和实际消费者另行验证，不能按对象所在旧地图直接删除 |
| FBO 复制删减、最终画面脏标记、原生等待归因 | 未实现；现有软件渲染 wall/CPU 差异不足以识别等待原因或证明可省去绘制 |

这次完成可安全集成的三项优化及其验证，快照/GC 的大幅降停顿和完整保存事务仍是未交付工作。
未知 hook、跨平台 writer、硬件 GPU 和云存档不能用当前单一角色的测试代替验收。

## 开关与验证入口

以下字段默认开启；设为 false 后重启游戏可独立关闭：

```lua
config.settings.faster_tome = {
    hotkey_text_cache = false,
    effect_mask_batch = false,
    save_callbacks = false,
}
```

其他现有配置可同时保留。源码来源和行边界检查属于兼容守卫，不是代码哈希认证。
完整回归运行 `bash tests/run.sh <engine-clone> <dlc-fixtures>`，新增 799 个快捷栏、876 个原生遮罩、562 个原生保存回调检查，均在 JIT 开关两种模式通过。
原生遮罩 fixture 使用固定引擎 GL 绑定、EGL llvmpipe，比较连续 RGBA、GL 状态、半透明叠加、格顺序、坐标截断和动画调用。
真实快捷栏完整 UI 的 120 帧、117,964,800 bytes RGBA 和 8,484 次业务调用对比已通过，三种阴影各 40 帧，GL 状态及栈深度恢复。
离屏像素差分在每对之间、FBO0 上完整 GC，对内暂停，隔离实际原生 FBO 析构解绑副作用；结束恢复常规 GC，不作为游戏计时。
真实游戏连续帧诊断和聚合证据入口见 [render evidence](../evidence/faster-tome4-render/README.md)。
安装包只包含可移植 Lua addon；C/EGL fixture 源码随测试发布，运行时编译到临时目录，没有随包原生二进制组件。
