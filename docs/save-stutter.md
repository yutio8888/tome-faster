**0.2.2：针对真实存档保存卡顿的简洁优化**

分支 `perf-save-stutter-20260912`，目标为 ToME 1.7.6，固定引擎提交
`624a67329fe2ad440c5b344785a9c73fcf22ae63`。本轮增加两个小模块：减少快照复制中的无效查询，以及省去本体离线消费者明确丢弃的角色资料生成。三组真实存档对照中，同步保存调用中位数由 **459.182 ms 降至 205.085 ms**。

[FasterClone.lua](../overload/engine/FasterClone.lua) 保留完整 `cloneForSave` 对象图，只把 memo 查询移到 `type(value) == "table"` 判断之后。memo 记录的是原表与克隆表的对应关系；数字、字符串、函数、线程和 userdata 无须查这张表。原遍历顺序、表键、共享引用、循环、元表、弱表属性和对象计数均保留，不调用 `cloned`。两处容易误改的细节也保留：`__SAVEINSTEAD` 遇到已有记录时仍返回原 replacement 并按本体计数；`__threads` 的值如果此前已被复制，仍使用已有克隆，而不是一律保留原引用。

安装器检查本体方法及递归 helper 的来源与行边界，只替换 `Game.cloneForSave`。来源不符时保留已有实现。这是固定版本的兼容性检查，不是代码哈希认证；没有按最终存档白名单删掉 UI 或其他快照字段。

[FasterChardump.lua](../overload/engine/FasterChardump.lua) 处理另一个热点。本体 `Player.saveUUID` 会生成完整 JSON、物品和技能描述并压缩，之后调用 `PlayerProfile.registerSaveChardump`。后者在 `auth` 不成立或 `hash_valid` 不成立时直接返回，既不发送，也不暂存供以后登录上传。本模块仅在这个明确丢弃分支、已有角色 UUID、`charball == nil`，且相关方法仍匹配已知本体时提前返回。

已认证且校验有效时照常生成在线资料；请求真实 charball、尚需注册 UUID、自定义导出方法或消费端、专用 `ToME:PlayerDumpJSON` hook 存在，以及 hook 分发器无法识别时，均保留原路径。这里的“离线”指本体消费者的认证条件，不是探测网络能否连通。插件不修改 `upload_charsheet` 设置。

guard 保护的是上述导出入口和专用 hook，**不代表所有描述层扩展都经过识别**。例如 `Object:desc*`、`Actor:getTalentFullDescription` 以及自定义技能描述仍可能扩展本体生成过程。当前存档中的相关 Ashes/Orcs hooks 只追加临时描述文本；其他 addon 若在这些入口执行额外业务，应关闭 `offline_chardump` 并验证。

原 `Party.cloneFull`、`stripForExport`、成员切换和保存队列完整保留。即使那份临时 party 最后没有上传，克隆及清理仍可能触发 UID 分配、RNG 或 `cloned/loaded` 回调，不能仅凭返回值未使用就删除。两项优化均通过常规 superload 安装，不改本体源码、存档格式、物品或战斗规则，也不调整 GC、粒子密度、着色器或绘制流程。

`config.settings.faster_tome.save_clone` 与 `offline_chardump` 均默认启用，分别设为 `false` 可在下次启动时关闭。已有 Faster 优化保持原有开关；对照测试只切换本轮这两项。

**真实保存结果**

输入为用户提供的同一份存档，角色位于 Dreadfell 9。环境为 Ryzen 7 9800X3D、ToME 1.7.6、LuaJIT 2.0.2、Xvfb + llvmpipe 软件渲染、约 30 FPS 上限，离线运行。每次从原始 ZIP 创建独立副本，加载后预热约 2 秒，执行正常保存；三对 before/after 共六次运行，全部完成且保存窗口的 `turn_delta` 为 0。

数据来自 `stutter-summary.json` 中的 `stutter-opt-{before,after}-pair{1,2,3}-01`。表内为各组三次的中位数，括号内为最小值至最大值，单位 ms。

| 指标 | 关闭本轮两项优化 | 开启本轮两项优化 | 中位数减少 |
| --- | ---: | ---: | ---: |
| `Game.saveGame` 同步调用 | 459.182（458.492–497.684） | 205.085（202.027–209.508） | 55.34% |
| 发起保存至观察到流程完成 | 911.499（864.724–913.396） | 619.968（610.377–640.548） | 31.98% |
| 每次保存的最长显示回调间隔 | 472.064（469.952–511.287） | 215.439（212.004–219.031） | 54.36% |

保存流程时长包含后台管线及完成观察延迟，不能全部算作主线程停顿；显示回调间隔也不是显示器呈现时间。同步调用仍约 205 ms，尚有进一步改善空间。本次两项同时切换的结果不能拆成各模块在整条保存流程中的独立贡献，也不能套用于在线资料正常上传的情况。

另在 `stutter-opt-clone-check-01` 对加载后的真实游戏图进行逐表验证：**127,833 张克隆表、509,503 个键值项、27,373 个本体计数对象完全一致**，同时核对元表、别名及保留原引用。表数量与本体对象计数含义不同，均不是最终 ZIP 条目数。

随后恢复正常函数环境，预热 3 对，执行 10 对交替克隆。每次先释放前次输出并完整 GC，前置 GC 不计时；实际复制时自动 GC 正常运行。原版中位数 **109.354 ms**（106.695–112.335），候选 **73.084 ms**（70.796–78.280），减少 **33.17%**。这是同一进程、同一真实图上的局部测量；完整图检查时为稳定弱表而暂停 GC，不计入性能样本，诊断代理与 GC 状态随后恢复。

回归测试覆盖既有 20,790 项基础断言，以及保存/加载 71、运行时 162、计时 22 项检查；新增克隆差分测试包含 91 个图、本次 73,284 项断言，角色导出测试 175 项检查。克隆测试已在 LuaJIT 2.0.2 和 2.1 上运行。图遍历会使具体断言次数略有变化；最新计数、各次样本、真实角色在线导出一致性与保存后重载记录，统一见 [save-stutter-results.json](save-stutter-results.json)。本地诊断模块不随 addon 分发，结果文件不包含完整存档对象图。

这些证据支持减少本存档的保存停顿。普通移动尚未复现严重逻辑长帧，战斗长帧此前主要落在本机软件渲染路径；本轮没有修改该路径，也不承诺消除移动或战斗中的渲染停顿。结论限于一个存档和上述环境，不能推算其他机器、硬件 GPU 或所有 addon 组合的收益。

最终真实角色检查也已通过：拦截网络发送后，在线原版与优化版的解压 JSON、标题及标签一致；仅对本体由 `pairs` 生成的集合顺序归一化，背包和技能列表顺序保留。离线 JSON 编码从 1 次降到 0 次，选定角色状态、UID 序列不变，Lua RNG 调用为 0。优化后存档重新加载、再次保存及 ZIP CRC 检查均通过，原始上传 ZIP 的 SHA-256 不变。
