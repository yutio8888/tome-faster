后续 0.2.12 已将库存归属压缩和 Fearscape 清理改为默认开启，base62 默认关闭，见
[当前默认配置](save-defaults.md)。本页保留 0.2.11 冻结包的独立测量与当时默认值。

2026-09-14。五个场景各完成 30 对、60 次保存，合计 300 次。每对使用同一个冻结包，仅改变一个新开关；下表只使用本轮数据。

三项新选项继续默认关闭。本次补充单项测量，没有修改生产代码或重打包。

## 各项收益的解释

单项结论如下。base62 相对已有十进制短编号减少 39,152 B 未压缩内容和约 17.3 KB 主档，没有减少对象条目；保存 CPU 上界未过门槛，当前证据不足以放行。

库存优化在这 24 件新增物品上减少 119,592 B 未压缩内容和约 24.9 KB 主档，条目数仍为 2,888；缩小来自归属记录表示，不是删除物品。无新增事件时旧归属表没有被迁移，主档只有 0.5 B 的中位数差，没有实质缩小。两个库存保存场景均通过本轮保存门槛；添加调用自身的平均 user CPU 增量为 0.1735 ms／24 件，95% 区间为 [−0.0080, +0.3550] ms，不能据此证明事件自身开销小于 1%。

Fearscape 成功退出组减少 5,000 B 未压缩内容、约 1.74 KB 主档和一个 NPC 条目。该施法者使用无行动 AI；测试没有证明整张 Fearscape 地图被释放。两侧新捕获共同替换旧引用带来的变化也不属于此单项收益。完整退出观察区间的 user CPU 增量为 7.0562 ms，95% 区间为 [−7.5877, +21.7001] ms，仍较宽。同步死亡调用只占其中一小部分，候选的一次 user 读数为零，不能将它描述为没有 CPU 成本。

两个无事件对照的未压缩字节及条目数完全不变，压缩输出的零星字节波动不算优化收益。Fearscape 无事件组仍观察到 −1.409% 的保存 user CPU 变化，双侧 95% 区间为 [−2.516%, −0.288%]。同一区间的主线程 user CPU 差为 +0.385 ms，95% 区间 [−5.924, +6.694] ms。全进程变化的机制未由本实验定位，不能用来声称执行引用清理获得了这部分收益。这也说明整段进程 CPU 变化与局部清理函数耗时需要分别解释。

四个保存场景通过各自的门槛，base62 未证明通过。事件、加载、组合开关和其他运行环境仍有独立范围限制，三个新选项保持默认关闭。

## 计量方法与范围

本次测试只比较同一个 0.2.11 包的开关差异。每一对 A/B 使用同一份旧档的新副本，A 显式关闭三个新选项，B 只开启该行对应的一项。已有十进制短编号、FBO 保护和 500 ms 受击提示间隔在两边相同。五个场景各固定 30 对，合计 300 次保存；每轮轮换场景起点，奇数对 AB、偶数对 BA。没有复用旧实验的基准，也没有合并不同场景的样本。

| 场景 | 唯一变化的选项 | 两侧都执行的工作 |
| --- | --- | --- |
| base62 保存 | `compact_save_names_base62` | 直接保存；对照为已有短十进制编号 |
| 库存，无新事件 | `compact_inventory` | 加载旧档后直接保存 |
| 库存，添加 24 件 | `compact_inventory` | 预先创建相同的 24 个标准 Object，调用实际 `Player:addObject(inventory_table, object, true)`，随后保存 |
| Fearscape，无新事件 | `fearscape_cleanup` | 加载旧档后直接保存 |
| Fearscape，施法者死亡退出 | `fearscape_cleanup` | 原技能进入，实际 `NPC:die(nil)` 触发退出，原游戏循环完成返回，随后保存 |

库存事件的计时包含 24 次完整调用及相同的循环／返回值记录；对象创建、断言、状态遍历在区间外。它不是全部拾取流程的计时：原生 `pickupFloor` 的数字库存参数、地面移除和排序等另有路径。

Fearscape 的进入／退出各保留同步调用与首次观察确认完成两个区间。完整观察区间包含原回调、调度、渲染、观察间隔及固定的少量诊断工作；它不是清理函数独占 CPU，也不是精确插在原回调最后一条指令上的时钟。诊断没有替换天赋或死亡回调，没有手动清理引用、执行回调或增加游戏回合。同步区间包含于对应完整区间，不能相加。

所有保存时间均在事件结束、状态验证完成之后开始。主指标是完整保存区间的全进程 user CPU，采用 `getrusage(RUSAGE_SELF).ru_utime`：从 `game:saveGame()` 前，到原保存 worker 返回、同步调用也已经返回，且 pipe、saving、waiton、on_done 全部完成。它包括该区间内工作的保存、渲染和粒子线程。同步保存、主线程 user/system、主线程总 CPU 和墙钟另列，不能替代主指标。

保存变化使用 30 个配对 `log(B/A)` 的几何均值；df=29 的 Student t 单侧 95% 上界严格小于 +1% 才记为该场景通过。每组的区间是各自的 95% 区间，并非五组共同覆盖的 95% 保证。全部固定有效样本保留，不删慢值、不扩样，也不按宿主 load 事后筛选。事件采用 30 个完整批次／退出事件的配对绝对差和两侧 95% t 区间，零读数保留；24 件物品不被当成 24 个独立重复样本。

每会话预热前记录 64 个空采样区间，不从事件结果中扣除。其零值比例、分位数和最大值只描述这次观测；微秒字段粒度与观测最大值都不是严格测量误差上界。极短事件的 user CPU 若不能分辨，不能称为零开销。主线程总 CPU 只作补充。另列的“事件 + 保存”仅相加两个互不重叠的已测区间，不包含场景准备、验证或两区间之间的空隙，也不表示角色整个生命周期的开销。

环境为 Linux x86-64、游戏内嵌 LuaJIT 2.0.2、Xvfb/llvmpipe、1280×800、Shockbolt 64×64、30 FPS、背景保存。联网、上传和 profiler 关闭。每次重新启动进程并复制相同 profile、shader cache 和原始存档；测量期间没有运行其他自建游戏、压缩基准或回归测试。

输入包 SHA256 为 `9464fdfc425f53a238aa76ffc16853bd9c5e38df9d6e9b5519941b517f5d2f76`，引擎 SHA256 为 `5aa8fe5cfa8f0cde3aa82deb4602be95d8f7668e7d5d2ea4ce450cae18248dc7`。最终计划 SHA256 为 `82ba2eede4edcf0c454a0ecafaada371c421493cb2b6a2fcdc79fa140398a2b3`。正式采样前完成两轮各十次预检；第二轮把库存返回值断言移出计时，增加显式归档校验与会话结束时间。第一版计划和预检保留，两轮预检均不计入正式样本。

结果仅适用于本旧档、这几个工作负载及本机环境。未测三开关同时开启的交互、模块首次加载 CPU、Windows、硬件 GPU或长时间游戏；各场景通过与否不能外推成所有场景或整个生命周期的 user CPU 增加小于 1%。

## 完整性、兼容性与结论

全部 300 次保存正常退出、无 Lua／coroutine 错误，保存前后状态投影一致；全部 150 对 A/B 的玩家、Actor、库存顺序及 UID 别名投影比较通过。所有 6,900 个归档的 CRC、唯一条目名和单一 `main` 检查通过。完整分析同时验证了预声明顺序、会话不重叠、输入文件、唯一开关、实际生效方法、计时终点以及固定来源。

三个实际生效场景各选预先约定的 candidate 第 1 对输出，完成两种读回，共六次全部通过：一是同一 0.2.11 包关闭三个新选项及 `load_queue`，确认调用原版 `Savefile.loadReal`；二是移除 Faster 和其他非官方游戏插件的运行环境，保留角色所需官方 DLC 及读档后诊断探针。后者仅调整测试副本 `desc.lua` 的插件依赖声明，所有串行化归档在读回前后逐字节不变。这验证对象数据可由原读取器处理，并不表示原版菜单会自动忽略缺失的插件依赖。真实旧档比较的是限定状态投影；完整测试图的原生写入／原版读回检查见原 [0.2.11 实现验收](save-compaction.md)。

最终复核 2,741 项环境文件、7 项测量源码／包、29 个生产文件和 67 个受保护存档文件均符合指纹；本体引擎的已跟踪文件、三个默认开关和发布包没有改动。此次只增加诊断、文档和证据，未重复运行已经通过且源码未变的完整生产回归。

每组每侧 1,920 个空采样区间的全进程 user CPU 中位数为 0.003–0.004 ms，p95 在 0.006–0.057 ms，最大观测在 0.082–0.107 ms；这些仅是预热前的描述统计，不构成误差界，也没有用于扣除事件结果。原始 19,200 个空区间和全部保存／事件起止时钟均已保留。

独立复算器从公开的全部 30 对原始标量重算了 102 项计时统计及各归档区间，与分析结果一致。主指标按 AB／BA 分开的描述统计、双侧区间和所有辅助指标可在 [机器可读结果](save-isolated-results.json) 查阅；未删样、扩样或合并旧队列。
