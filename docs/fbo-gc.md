# FBO 回收保护（0.2.8）

1.7.6 的原生 `gl_free_fbo` 在释放旧 framebuffer 时绑定该对象，解绑到 0 后没有恢复入口绘制目标。Lua GC 可以在一帧绘制中调用它，后续绘制因此使用错误目标。Linux 软件渲染实验中，这条路径与额外 LLVM 编译及长帧有关，但并非所有停顿都来自它。

本版本用纯 Lua 调整资源释放时机。`FBOGCGuard.lua` 保留原始 `__gc` 和 `use`，把待回收 userdata 放入强引用队列；下一次正常 `fbo:use(...)` 开始前调用原始析构，随后立即执行原始 `use`。绘制目标由这次原本就要发生的绑定操作设置，清屏、矩阵和视口仍按原调用处理。

两个队列交替使用：如果处理一批对象期间又发生回收，新对象留在另一队列中等待下次绑定。队列复用，不在每帧分配新队列表。保持存活的 Lua 关闭哨兵在 `lua_close` 时释放剩余队列，并让后续析构直接执行。ToME 返回主菜单会重建 Lua VM 并保留 GL 上下文，因此不能只依赖进程退出释放资源。

源码依据是固定引擎提交 `624a67329fe2ad440c5b344785a9c73fcf22ae63` 的 `src/core_lua.c`（`gl_free_fbo`、`gl_fbo_use`）、`src/auxiliar.c`（userdata 元表）及 `src/main.c`（`boot_lua`）。Lua 的外部资源终结语义见 [Lua 5.1 手册](https://www.lua.org/manual/5.1/manual.html#2.10.1)。

## 配置与兼容性

默认启用。要关闭，请在引擎配置中设置并重启：

```lua
config.settings.faster_tome.fbo_gc_guard = false
```

安装要求 FBO 的 `__gc` 和 `use` 仍是原生 C 函数；缺少运行时接口、元表或检测到已有 Lua 包装时跳过并记录原因。重复安装不会叠加包装。该检查不是引擎代码的密码学验证，也不能阻止之后其他 addon 再次替换方法。

此实现与独立验证原型的 helper 字节一致，沿用同一安装标记；独立原型和 Faster ToME4 都存在时不会重复包装。不过 Faster 的关闭选项不会撤销其他 addon 已安装的保护，做开关对照时应只加载一份实现。

保留原有 `faster` addon 身份，现有依赖它的存档可以解析到更新后的版本。无需新增平台 DLL／SO，也不改变技能、伤害逻辑、画质、动画生命周期、全局 GC 参数或保存时的三次完整 GC。FBO 本身会多保留到下一次 `use`；如果后续完全不再调用 `use`，队列保留到 Lua 关闭。

## 验证与测量边界

`tests/test_fbo_gc.lua` 在独立 EGL 上下文中编译并执行固定引擎的实际 FBO 绑定代码：先复现原始析构留下绑定 0，再验证 addon 下的绑定、全部目标像素、嵌套矩阵／视口、延后释放和多轮 GC。另一个 C 宿主用资源计数模拟错误析构，验证 533 个资源在 `lua_close` 前后恰好释放一次；重入测试验证释放过程中新增的 3 个资源也恰好释放一次。图形绑定测试与生命周期模型的范围不同。

新套件在 JIT 开启／关闭时各通过 25 项检查。完整游戏原型也分别通过禁用／启用条件下的真实 GL 绑定和像素检查：入口绑定 24 在原行为回收后变为 0，启用后保持 24；RGBA 64,128,191,255 的测试像素保持一致，待释放 FBO 在下次正常绑定时确认删除。

独立原型性能小样本预先固定为四对无修复的干净引擎 C99 记录、两对 D99 源码范围记录。每次从相同战前副本与缓存恢复，通过真实按键启动火雨，再等待五次；环境为 Linux Xvfb、Mesa llvmpipe、1280×800、30 FPS。12 次有效恢复包含 6,878 个帧间隔和 60 次等待，无帧／采样缓冲丢失及采样定时合并。

| 干净原引擎，四对恢复 | 原行为 | addon |
| --- | ---: | ---: |
| 出现 >50 ms 帧的恢复 | 4/4 | 2/4 |
| >50 ms 长帧 | 9 | 2 |
| 最长帧 | 88.08 ms | 54.18 ms |
| 含 LLVM 绘制叶样本的长帧 | 4 | 0 |

普通帧 CPU 按各次恢复的中位数配对，增加 0.02899 ms（0.77%）；等待视觉结束的配对差值为 +4.91 ms，两条件约为 1.46 秒。两对 D99 中最长帧从 95.66 ms 变为 49.25 ms，但 `native_set=core` 没有记录逐次 GL draw 区间，不能用它逐个归因 GL 调用。两条件均记录到 14 次原生 FBO 析构，保护并未跳过释放。[完整脱敏数值](fbo-gc-results.json)

这些是描述性小样本，不能推出稳定改善比例、排除小幅成本或宣称卡顿根除。两条件本批均没有 >100 ms 帧，未复现此前约 400 ms 的稀有停顿；Windows、硬件 GPU、长期运行和任意 addon 组合仍未验证。

集成后的回归与加载检查见 [验证记录](../evidence/faster-tome4-fbo-gc/README.md)。仓库只保存源码、测试和脱敏汇总，完整角色存档与原始游戏日志保留在本地。
